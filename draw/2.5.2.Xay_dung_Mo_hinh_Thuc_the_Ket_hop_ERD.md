# 2.5.2. Mô hình Thực thể Kết hợp (ERD) — Hướng dẫn & Bản trình bày chi tiết

Tài liệu này là một hướng dẫn chi tiết để xây dựng, trình bày và phiên bản hóa ERD cho hệ thống VieGo Blog. Nó bao gồm hợp đồng (contract) cho mô hình, danh sách thực thể và thuộc tính, các ràng buộc toàn vẹn, ví dụ SQL DDL, mã `dbdiagram` để import nhanh, và kịch bản trình bày chi tiết (slide + speaker notes).

---

## Hợp đồng (Contract)

- Mục tiêu: Mô tả cấu trúc dữ liệu chính, đảm bảo hiểu thống nhất giữa các nhóm, và cung cấp đầu vào cho việc triển khai migration/ORM.
- Inputs: yêu cầu nghiệp vụ, migration hiện có (`backend/migrations/`), models hiện tại (`backend/models/` nếu có), dữ liệu mẫu.
- Outputs: 1) file ERD (PNG, drawio hoặc dbdiagram), 2) SQL DDL mẫu, 3) tài liệu trình bày (slides + speaker notes).
- Tiêu chí thành công: ERD phản ánh chính xác các bảng quan trọng, quan hệ, ràng buộc; nhóm backend chấp nhận; có thể chuyển đổi thành migration/DDL.

## Phạm vi tập trung

- Chức năng cốt lõi: Người dùng (auth/profile/role), Nội dung (post/story/category/tag), Tương tác (comment/like/follow), Tour & Booking, Thông báo & Chat, và các bảng phụ trợ (attachment, image, rating).

---

## 1. Thực thể (Entities) — danh sách chi tiết

Lưu ý: phần thuộc tính chỉ liệt kê các trường quan trọng; khi triển khai, bổ sung index/constraint/unique theo yêu cầu nghiệp vụ.

- User

  - id (PK, bigint/UUID)
  - email (UK)
  - password_hash
  - status (ENUM: ACTIVE, BANNED, PENDING)
  - created_at, updated_at

- Profile

  - id (PK)
  - user_id (FK → User.id)
  - full_name
  - avatar_url
  - province
  - bio

- Role

  - id (PK)
  - name (UK)
  - description

- UserRole (junction)

  - user_id (FK)
  - role_id (FK)

- Post

  - id (PK)
  - author_id (FK → User.id)
  - title
  - slug (UK)
  - content (TEXT)
  - status (ENUM: DRAFT, PUBLISHED, ARCHIVED)
  - published_at

- Story (mở rộng Post)

  - id (PK)
  - post_id (FK → Post.id, UK)
  - province
  - location
  - is_archived

- Category

  - id, name, slug

- Tag

  - id, name

- PostTag (junction)

  - post_id, tag_id

- Comment

  - id (PK)
  - post_id (FK → Post.id)
  - user_id (FK → User.id)
  - parent_comment_id (nullable FK → Comment.id)
  - content
  - created_at

- Like

  - id, user_id, post_id (or comment_id), created_at

- Tour

  - id, seller_id (FK → User.id), title, description, price, duration, start_date

- Booking

  - id, tour_id (FK), customer_id (FK → User.id), quantity, total_amount, status, created_at

- TourImage

  - id, tour_id, url, caption

- Rating

  - id, target_type (ENUM), target_id, user_id, score, review

- Notification

  - id, recipient_id (FK → User.id), type, payload (JSON), is_read, created_at

- Conversation / Message / Attachment
  - conversation.id, message.id (conversation_id FK), sender_id, body, created_at
  - attachment.id, message_id, url, mime_type

---

## 2. Quan hệ chính (Relationships) & Cardinality

- User 1—N Post
- User N—N Role (qua UserRole)
- Post 1—N Comment; Comment tự tham chiếu 1—N cho thread
- Post N—N Tag (qua PostTag)
- Story 1—1 Post
- Tour 1—N Booking; Tour 1—N TourImage
- Booking 1—1 PaymentTransaction (nếu có)
- Conversation 1—N Message; Message 1—N Attachment
- Notification 1—N User (recipient)

Lưu ý: với quan hệ N—N, luôn dùng bảng trung gian có PK composite hoặc surrogate PK tùy nhu cầu truy vấn.

---

## 3. Ràng buộc toàn vẹn và chỉ số (Constraints & Indexing)

- PK cho mọi bảng.
- FK áp dụng ON DELETE CASCADE hoặc SET NULL tùy nghiệp vụ (ví dụ: xóa user có thể SET NULL author_id hoặc cấm xóa).
- Unique: email trên User, slug trên Post/Category.
- ENUM/bảng tham chiếu cho status/type.
- Index: index trên foreign keys, search fields (title, slug), created_at để phân trang.

## 4. SQL DDL mẫu (Postgres-like) — ví dụ cho các bảng chính

```sql
CREATE TABLE "user" (
	id BIGSERIAL PRIMARY KEY,
	email VARCHAR(255) NOT NULL UNIQUE,
	password_hash VARCHAR(255) NOT NULL,
	status VARCHAR(20) NOT NULL DEFAULT 'ACTIVE',
	created_at TIMESTAMP NOT NULL DEFAULT now(),
	updated_at TIMESTAMP NOT NULL DEFAULT now()
);

CREATE TABLE profile (
	id BIGSERIAL PRIMARY KEY,
	user_id BIGINT NOT NULL REFERENCES "user"(id) ON DELETE CASCADE,
	full_name VARCHAR(255),
	avatar_url TEXT,
	province VARCHAR(100),
	bio TEXT
);

CREATE TABLE post (
	id BIGSERIAL PRIMARY KEY,
	author_id BIGINT NOT NULL REFERENCES "user"(id),
	title VARCHAR(512) NOT NULL,
	slug VARCHAR(512) NOT NULL UNIQUE,
	content TEXT,
	status VARCHAR(20) NOT NULL DEFAULT 'DRAFT',
	published_at TIMESTAMP
);

CREATE TABLE comment (
	id BIGSERIAL PRIMARY KEY,
	post_id BIGINT NOT NULL REFERENCES post(id) ON DELETE CASCADE,
	user_id BIGINT REFERENCES "user"(id),
	parent_comment_id BIGINT REFERENCES comment(id) ON DELETE CASCADE,
	content TEXT NOT NULL,
	created_at TIMESTAMP NOT NULL DEFAULT now()
);
```

## 5. Mã `dbdiagram` để import nhanh (ví dụ cơ bản)

```dbml
Table user {
	id bigint [pk]
	email varchar [unique]
	password_hash varchar
	status varchar
	created_at timestamp
}

Table post {
	id bigint [pk]
	author_id bigint [ref: > user.id]
	title varchar
	slug varchar [unique]
	content text
	status varchar
}

Table comment {
	id bigint [pk]
	post_id bigint [ref: > post.id]
	user_id bigint [ref: > user.id]
	parent_comment_id bigint [ref: > comment.id]
	content text
}

Ref: post.author_id > user.id
Ref: comment.post_id > post.id
Ref: comment.user_id > user.id
```

Bạn có thể dán phần dbml trên vào https://dbdiagram.io/import để nhanh chóng sinh ERD và SQL.

- Bình luận đa cấp: giới hạn độ sâu hoặc dùng giải pháp paginated thread.
